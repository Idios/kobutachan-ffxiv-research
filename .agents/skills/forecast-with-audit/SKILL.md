# 監査つき予測

## 使う場面

次のような予測・推定を作るとき。

- データの自然な地平を超える（複数年）
- 収集の不規則性が既知の公開データ・第三者データに乗っている
- 改訂され、反論され、それに耐えなければならない

機械検査の側は `analysis-integrity` と組で使う。

## 読み方（初回に必ず）

- **手順4・5は「あなたがモデルとデータを持つ」前提で書かれている。** モデルの無い主張（他人の点推定など）を監査する場合は、まず最小の監査可能な形（モデル＋尺度規約）へ再構成し、再構成できないなら「反証不能＝不合格」と判定してよい。
- **「ここでは」に続く数値は、このスキルを抽出した元分析（FFXIV 3年予測）の実測値である**（例: 18.1pt→1.4pt、−25%〜+4%、8.7pt / 15.3pt、致命的5件）。一般の定数でも、あなたの課題に使う値でもない。**あなたの課題の数値は自分のデータから導出し、元分析の数値を写さないこと。**
- **用語**:
  - **尺度規約** = 数値を比較する前に宣言する 5 軸（観測窓・集計閾値・通貨基準・集計規則・位相）
  - **識別** = 推定量がデータで範囲を絞られている度合い。入力を妥当な範囲で振っても報告精度より大きく動くなら「識別されていない」
  - **帯** = 点推定の代わりに出す値の範囲。識別されていない量は帯で出す
  - **走査箱** = 帯を作るときに走査するパラメータ範囲。帯の一部で、箱なしで帯を引用してはならない
  - **バックキャスト** = 完成した期間にモデルを当て実績と比べ、偏り（バイアス）を測ること
  - **点推定** = 単一の値。識別されていない量を点で出すのを避ける
  - **位相** = 周期（拡張リリース、季節イベントなど）のどこに観測点が位置するか。周期の異なる位相どうしを直接比較しない
  - **pt** = パーセンテージポイント（百分率の差）。帯幅・寄与の数値を書くときは分母（何に対する百分率か）を併記する
  - **ρ / I** = 手順4の元分析のパラメータ名。ρ＝定着（既存継続）、I＝流入（新規）。一般には「初期状態に比例する成分」と「流入に比例する成分」に分け、打ち消しを測る

## 手順

### 1. データに触れる前に、尺度規約と禁止事項を宣言する

フェーズ0で次を固定する。

- **リサーチクエスチョン**を番号つきで。後に必ず「答えた」か「答えられない」と明示する
- **全系列の尺度規約** — 観測窓、集計対象の閾値、通貨基準、集計規則（等観測 vs 時間加重）、そして**周期上の位相**
- **禁止事項**を名指しで。例:「窓長を正規化していない生系列で増減を論じること」

宣言し損ねた軸は必ず後で誤差になる。ここでは5軸必要で、4軸を宣言し、5番目（位相）を落とした結果、第13次で致命的誤りが出た。

### 2. モデルを作る前に許容誤差を固定する

モデルを書く前に、日付つきのファイルへ記録する: バックテストの対象、合否の許容誤差、何をもって不合格とするか。**後から緩めない。** これが無いと、落ちたバックテストが合格に読み替えられる。

### 3. すべての主張に根拠の等級を付ける

`[Fact]` 一次資料 ・ `[Observed]` 観測値 ・ `[Company]` 当事者の発言 ・ `[Estimate]` 推定 ・ `[Hypothesis]` 仮説。

これらを混ぜると、3フェーズ先で仮説が前提に化ける。

### 4. バックキャストしてバイアスを測る

完成したモデルを**完了した**期間に当て、実績と比べる。

```
バイアス = 完了周期の予測平均 / 完了周期の実測平均 − 1
```

**バイアスを測れない場合（完了した期間がまだ無い、または監査対象にモデルが無い）:** 数値を捏造せず「未測定（較正不能）」と報告し、その点推定を較正不能として不合格にする。「測った」と装わない。較正不能の点推定は信頼性を論じる土台そのものが無い。

補正は**下流の全量に一貫して適用する** — 人口・売上・利益。片方だけ補正すると、文書どうしが食い違う。

**補正が何を測っていないかを知る。** バックキャストの実測平均が比較の分母と同一であるとき、補正後の指標は `w / cp − 1`（モデルの予測 ÷ 同じモデルの当てはめ）に帰着する。すなわち **in-sample の再較正比**であり、分子と分母を比例的に通過する前提は打ち消される。ここでの狭さは定義的帰結であって頑健性ではない。

ただし**打ち消しは仮定せず測る**。「ρ と I は定義上打ち消される」は誤りだった。実測では ρ はほぼ打ち消す（18.1pt → 1.4pt）が **I は打ち消さない**（27.3pt → 6.5pt）。予測が観測された初期状態から出発し、その初期値が流入に比例しないためである。決め手は**分子と分母それぞれにおける寄与シェアの差**であって、同次性ではない。

### 5. 主指標が識別されているか検査する

点推定を出す前に、全入力を識別された範囲いっぱいに振る。

- 報告する精度より小さくしか動かない → 点推定でよい
- 報告する精度より大きく動く → **その量は識別されていない。点で出すのをやめる**

系列が複数ある場合は**主指標を1つ明示**し、残りも同じ規約・同じ識別検査で帯化する。入力の振り幅すら決められない場合（尺度規約・データが無い）は、その点推定を識別検査未通過として扱い、点で出さない。

ここでは生の指標が −25% から +4%（約30ポイント）まで動いた。13ラウンドにわたって改訂のたびに動き続けたのは、**識別されていない量は収束しえない**からである。**代わりに帯を出す。** 帯は、較正が打ち消さない前提だけで作る。

### 6. 帯は走査箱とセットで宣言する

パラメータ空間の走査から帯を作るなら、**箱は答えの一部である**。両端が常に格子の端に来るなら、縛っているのはデータではなく箱である。

ここでは採用箱で 8.7pt、プロジェクトが別の場所で既に宣言していた広い箱では 15.3pt となり、**どの不確実性源が最大かが入れ替わった**。箱の感度表を載せ、箱を書かずに帯を引用しない。

### 7. 反証テストを事前設定の閾値で書く

各テストに明記する: 観測対象、閾値、**何を撤回するか**、同じ観測を生む交絡。

確認すべき失敗が2つある。

- **到達不能な閾値** — あるテストは、全履歴で一度も到達していない水準を要求していた
- **連続量の判定に離散的な撤回** — 判定条件が連続量なら、撤回内容も連続的な更新でなければならない。特定の代替値へのジャンプにしてはいけない

閾値はモデルから導出し、シナリオが含意する範囲で到達可能なことを確かめる。

### 8. 敵対的査読ラウンドを回す

各ラウンドは**前ラウンドの訂正**を狙う。次の致命的誤りはそこにいる。査読者にはスクリプトを渡し、通読ではなく**独立の再計算**を要求する。

ラウンドごとに根本原因を名付けて記録する。名付けても再発は止まらない（`analysis-integrity` 参照）が、再発が見えるようにはなる。

### 9. 収束を主張する前に静止ラウンドを回す

通常のラウンドは書き換えた直後の材料を見るので、件数が少なくても「あまり書かなかった」ことしか意味しない。**数ラウンド手を入れていない文書を査読する。**

ここではそれで致命的5件が出た。原因はすべて、下流の正典が更新されたのに上流がそれを受け取っていなかったことである。**静止は収束ではなく、取り残されである。**

### 10. 収束を正直に報告する

ラウンド別の致命的件数を数列で公開する。収束していないなら、そう書き、**2つの別の失敗に分ける**。

- **識別の失敗** — 推定量がデータで pin されていない。帯にすることで解決する。検証可能: 帯は以降の査読ラウンドを通過し、その間に点推定はまた動いた
- **成果物の整合の失敗** — 正典の更新が伝播しない。**査読では解決しない。** 査読は事後に見つけるだけで生成を止めない。道具が要る

この2つを混ぜると、「片方を直したら両方直った」という誤った主張になる。

## 検証

- [ ] 全系列に窓・閾値・通貨基準・集計規則・位相が明記されている
- [ ] コミットメントの記録が最初のモデル実装より前の日付で、後から緩められていない
- [ ] バックキャストのバイアスを測り、**下流の全量**に適用した
- [ ] 補正による打ち消しを、前提ごとに**測った**（仮定していない）
- [ ] 識別の検査を行い、点が報告精度より大きく動くなら帯にした
- [ ] 全ての帯が走査箱つきで、箱の感度表がある
- [ ] 全ての反証閾値が到達可能で、撤回内容が判定条件と同じ尺度である
- [ ] 静止ラウンドを回した
- [ ] ラウンド別の件数を公開し、収束の有無を正直に書いた

## 収束していないときの書き方

> これは検証し尽くした結果ではなく、Nラウンド目で打ち切った途中経過である。主指標の**向き**はNラウンドすべてで不変であり、定性的結論21件のうち16件は一度も覆っていない。収束しなかったのは点推定 —— 現在は帯に置き換えた —— と、分析の道具立てのほうである。

## 同梱スクリプト

予測・監査に必要なスクリプトとデータを同梱している。`20260830_1/` はアーカイブで、**ここが正典**。

| 手順 | スクリプト |
|---|---|
| 正典パラメータの登録簿 | `scripts/params.py` |
| 予測エンジン（ストック・フロー） | `scripts/phase7_forecast.py` |
| バックキャスト（バイアス測定） | `scripts/phase7_backcast.py` |
| 識別検査・帯の生成 | `scripts/phase13_identification.py` |
| 走査箱と感度 | `scripts/phase8_sensitivity.py` |
| 反証テストの設計 | `scripts/phase8_falsification.py` |

`data/` も同梱している。実行はスキルのルートで `./run.sh <name>.py`（Windows の既定エンコーディング問題を避けるため UTF-8 モードで起動する）。
