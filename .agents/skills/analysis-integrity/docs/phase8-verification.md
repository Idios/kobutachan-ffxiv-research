### 0-1d. 「収束しない量を結論から外す」は効いたのか — 【第15次で新設】

**効いた。ただし対象を取り違えていた。** 第13次は「点推定を帯に替えれば収束する」と読める書き方をしたが、これは誤りである。**指摘が出続ける原因は2つあり、点推定の識別問題はそのうち1つでしかなかった。**

| 量 | 第13次 | 第14次 | 第15次 |

#### 実測2: 直近11件の致命的誤りのうち、「点推定が動いた」ものは**ゼロ**

#### 2つの失敗を分ける

| | **失敗A: 推定量が識別されていない** | **失敗B: 成果物の整合が保てない** |
|---|---|---|
| 症状 | 前提を変えるたびに答えが動く | 正典が動くたびに文書が誤りになる |
| 原因 | データが量を pin していない | 数値が16本の文書に手で書かれている／比較の基準を人間が判断している |
| 第13次の処置 | **点推定を帯に替えた → 解決** | **何もしていない** |
| 現状 | 帯は2ラウンド不変 | **直近11件中9件がここ** |

**第13次の「収束しえない量を結論に置いていたから収束しなかった」は、失敗Aの説明を失敗Bにも当てはめた誤りである。撤回する。**

#### 失敗B は査読では収束しない

失敗Bは**成果物を書くたびに新しく作られる**。査読は事後に見つけるだけで、生成を止めない。実際、根本原因を命名し節を書いて対処を実装しても、D-1・D-2・D-4・D-13 は15ラウンド一貫して再発している。

**したがって第15次は、検出ではなく「起こせなくする」ことに手を入れた:**

| ガード | 何を不可能にしたか | 実装 |
|---|---|---|
| **`params.compare_census()`** | **窓長・足切りレジームが揃っていない国勢調査の比較**。生の総数どうしを割る／レジームが違うまま比べる／窓長正規化していない列で比べる、はいずれも `ScaleMismatch` 例外になる | D-4 を検出から**不可能**へ |
| **`groupA(box=...)` / `groupA_label()`** | **走査箱を宣言しない帯の取得**。箱は引数で受け取り、**結果に同梱して返す**ので、箱を書かずに帯を引用できない | D-13 を検出から**不可能**へ |
| **旧値の不在検査（全文書）** | 正典が動いたときに旧値が文書に残ること。**「正しい値が存在するか」ではなく「旧値が残っていないか」を測る** | D-1・D-2 の**検出**を全16本へ拡張（第14次までは2本のみ） |

**検査 P** がこの3つの発火を毎回確認する（6/6）。**ガードが発火しないガードは無意味なので、ガード自体を検査対象にした。**

> **見通し**: 失敗B のうち **D-1・D-2（滞留）は機械化で 0 に近づけられる** —— 究極的には文書の数値を手書きせず生成物にすればよい。**D-4・D-13 は判断の失敗なので、ガードで塞げるのは「既知の形」だけである。** 新しい比較・新しい手続きを作れば、同じ誤りの新しい形が生まれる。**したがって「指摘が 0 になるラウンド」は、新しく作るのをやめた場合にしか来ない。**

## 4. 第3次監査（6件）— 敵対的査読

### 4-1. 【致命的 C1】「非パラメトリック検証」は OLS の恒等式であり証拠として空だった

v0.4 の中心証拠は「正しい定式化は生データの世代別平均を最大 0.008 の差で再現し、誤仕様は 0.043 外れる。**尤もらしさの議論ではなく再現するかしないかの問題である**」だった。

**「実測」と称した量は、定式化③自身の窓長係数でデータを正規化したものだった:**

```
「実測」_i = (継続_t/総数_{t−1}) × (64/w_t)^(+0.1173) × (64/w_{t−1})^(+0.2200)
             指数 +0.1173 と −0.2200 は ③ 自身の推定値
```

**世代ダミー付き OLS は世代別の残差和がゼロなので、世代別幾何平均＝当てはめ値は代数的恒等式である。** 誤仕様の式でも、その式自身の係数で正規化すれば完全に再現する（差 0.000000）。**文書が言う「誤仕様は 0.043 外れる」は、①の当てはめ値を③の正規化規約で測っただけだった。**

### 4d-1. 【致命的 R6-1】感度分析の群A が「バックキャストの許容域」と称しながら、端点が全て域外だった

第5次 C1 の対処として導入した群A/群B の分割そのものが誤っていた。群Aは「バックキャストの許容域で両側に振る（相互比較できる）」と宣言していたが、実際の端点は:

| ケース | S\* = I/(1−ρ) | 許容域（684,211〜830,000）内か |
|---|---|---|
| ρ=0.74 / I=採用 | 648,592 | **域外** |
| ρ=0.80 / I=採用 | 843,170 | **域外** |
| I=140,000 / ρ=採用 | 667,962 | **域外** |
| I=200,000 / ρ=採用 | 954,231 | **域外** |

**5点中5点が域外。** 周辺レンジ (0.74, 0.80) / (140k, 200k) は**結合許容集合の各軸への射影**であり、その端点は「相手を最適に選べば到達できる」点である。相手を採用値に固定したまま端点へ振れば結合制約を外れる。

**帰結**: v1.1 の「最大の分散源は ρ ではなく I である（27.7pt 対 18.3pt）」は**不確実性の分解ではなく、許容されない反実仮想どうしの差**だった。順位づけを撤回し、較正基準を4群（結合許容域／測定・規約由来／周辺レンジの一次元摂動／設計選択）に再編した。

### 4d-2. 【致命的 R6-2】S\* 許容域が粗格子の産物で、「採用値は域外」という最重要の留保が反転した

第4次 F2 が導入した `SSTAR_RANGE_BACKCAST = (700,000, 770,833)` は、Δρ=0.02 / ΔI=15,000 の粗格子から出ていた。端点 700,000 = 140,000/(1−0.80)、770,833 = 185,000/(1−0.76) は**いずれも格子ノードそのもの**である。許容率（MAE 最小の何倍まで許すか）も 1.5 倍固定で、根拠が書かれていなかった。

| 格子 | 組数 | MAE最小 | ×1.25 | ×1.5 | ×2.0 |
|---|---|---|---|---|---|
| 粗（Δρ=0.02 / ΔI=15,000） | 36 | 4.08% | 域外 | **域外** | 域内 |
| 中（Δρ=0.01 / ΔI=5,000） | 187 | 3.97% | 域外 | **域内** | 域内 |
| 細（Δρ=0.005 / ΔI=2,500） | 693 | 3.81% | 域外 | **域内**（684,211〜830,000） | 域内 |

**刻みを細かくすると採用値 804,579 は域内に入る。** 域外になるのは許容率を ×1.25 まで絞ったときだけで、×1.25 を選ぶ理由はない。

**帰結**: final-report v1.1 が「**本レポートで最も重要な留保**」と明記していた「採用 S\* は許容域の外側」を撤回した。**これは第6次で唯一、結論を楽観方向に動かした所見である。** ただし格子に依存しない事実（採用点の MAE 6.45% は最良点 4.30% の 1.50 倍、周期平均を +2.1% 上振れさせる）は残り、バイアス補正の根拠はそちらへ移した。

**第5次 C2 は「結論側の格子が粗い」を直したが、制約側の格子は無検査のままだった。**

### 4d-3. 【致命的 R6-3】足切り丸めの感度が、4成分のうち1成分しか振っていなかった

第5次 M2 が「足切り段差は3経路に同時に効く」として導入した感度は、**total 段差（95/102）だけ**を振っていた。しかし丸めは4成分すべてに乗り、経路は次の通り:

**とくに new は1桁（5±0.5 = ±10%）なので、丸め幅は total（±0.5%）より桁違いに大きい。** さらに真値は加法制約 `new+ret+cont = total` を満たす（旧基準 8+31+63=102 は厳密に成立、新基準 5+28+61=94≠95 のずれ自体が丸めの証拠）。

ところが v5 までは **7.0 ローンチ窓（2024-08-27）の流入を I_BASE_LV80（2025-09〜2026-07 の5点）で割って 1.7434** としていた。**分子は 7.0 直後、分母はその1〜2年後で、周期上の位相が2年ずれている。** 分母はその間に減衰しているので倍率は系統的に過大に出る。

**位相を揃えて、観測できる3回のローンチすべてで測り直した:**

| 拡張 | ローンチ窓 | 発売からの日数 | 倍率 |
|---|---|---|---|
| 5.0 | 2019-07-29 | 27 | 1.5476 |
| 6.0 | 2022-01-03 | 27 | 1.0819 |
| 7.0 | 2024-08-27 | 56 | 1.4222 |

**n=3、平均 1.3506、範囲 1.0819〜1.5476。旧採用値 1.7434 は観測3回の範囲の外側にある。**

影響: **主指標（生）−8.9% → −8.9%**。ただし**バイアスも +5.0% → +2.2% に下がるので、補正後は −11.0% → −10.9% でほとんど動かない**（§4f-7）。

> **なぜ12ラウンド見つからなかったか。** 第7次 F2 が「分母をモデルが掛ける当の量に揃える」と訂正したときに、**単位を揃えることと推定対象を正しく選ぶことを取り違えた。** 分母を I_BASE にすれば数値の単位は合うが、それは「7.0 のローンチは**今の**水準の何倍だったか」という過去の事実であって、「8.0 のローンチは**今の**水準の何倍になるか」の推定ではない。**訂正そのものが次の誤りを作る**という本プロジェクトの最頻パターンの、もっとも典型的な例である。

### 4f-7b. 【第13次の第一稿が犯した誤り — 査読で摘出、撤回する】

**第一稿は「3量を振っても補正後は 7pt しか動かないから頑健」と主張した。これは誤りだった。**

バックキャストの観測平均 co は CYC7_MEAN と**厳密に一致する**（同じ系列だから）。したがって

> 補正後 = w/(1+bias)/CYC7_MEAN − 1 = w/(cp/co)/co − 1 = **w/cp − 1**

ここで w は 8.x の予測平均、cp は**同じモデルが 7.x に出す予測平均**である。つまり補正後の主指標は「**モデルを 7.x 平均に in-sample で再較正した比**」であり、**分子と分母を同じように通過する前提（ρ・I・足切り段差）は定義上打ち消される。**

**狭さは較正の定義的帰結であって、頑健性ではなかった。** 実行して確認済み（`phase13_identification.py` §A が恒等式を印字する）。

**もう1件、第一稿は訂正そのもので新しい誤りを作っていた。** 予測用のローンチ倍率を 1.3506 に直したとき、**バックキャストにも機械的に同じ値を適用した。** ところがバックキャストのローンチ窓では流入は**実測されている** —— 1.7434 × I_BASE = 298,404 は 7.0 ローンチ窓の実測流入そのものである。1.3506 を入れるとバックキャストがローンチ窓を **22.5% 過小に予測**し、その分「上振れ」が小さく見えていた（+5.0% → +2.2%）。**推定対象が違う**（予測は「8.0 でどれだけ跳ねるか＝未知」、バックキャストは「7.0 でどれだけ跳ねたか＝既知」）ので、**倍率を分離した**（`LAUNCH_MULT` と `BACKCAST_LAUNCH_MULT`）。バイアスは +5.0% に戻る。

> **これで第13次だけで致命的3件になった。** 内訳: (1) ローンチ倍率の位相ずれ（元の摘出）、(2) その訂正をバックキャストに誤適用、(3) 補正の頑健性の誤主張。**(2) と (3) は、(1) を直す作業そのものが作った誤りである。**

### 5-0. 【第4次で新設】D-9: 集計の規約が結論を動かすのに、規約が宣言されていなかった

これは D-5（スケール軸の宣言）の**第4の軸**として扱うべきものである:

| 軸 | 内容 |
|---|------|
| A | 窓長: raw / norm64 |

| **D【新】** | **集計規約: 等観測重み / 時間重み / 位相整合 / 単純平均** |

### 5-0b. 【第5次で新設】D-10: 感度分析の較正基準を揃えないと順位が意味を失う

> **D-10: 「どの前提が結論を最も動かすか」を並べるとき、各前提の低位/高位ケースが違う基準で選ばれていると、順位は「不確実性の大きさ」ではなく「振り幅の設定の恣意性」を反映する。**

第5次監査 C1 がその例である。ρ は**バックキャストの許容域**から、I_base は**片側の摂動**から取っていた。同一基準に揃えると順位が逆転した（ρ 18.3pt < I_base 27.7pt）。

**対処**: 較正基準を宣言し、**基準の違う前提を1つのランキングに混ぜない**（群A/群B）。これは D-5（スケール軸の宣言）・D-9（集計規約の宣言）と同型で、**「宣言しないと比較できない属性」の第3の種類**である:

| 種類 | 何を宣言するか |
|---|---|
| D-5 | スケール軸（窓長・足切り基準・為替） |
| D-9 | 集計規約（等観測重み／時間重み／位相整合） |
| **D-10** | **感度の較正基準（許容域で両側／片側の摂動）** |
| **D-12【第6次で新設】** | **結合でしか制約されない量を周辺に分解して比較した**（§5-0d） |
| **D-13【第6次で新設】** | **検証手続き自身のメタパラメータ（格子の刻み・許容率・振る対象）が未宣言・未感度**（§5-0e） |
| **D-14【第6次で新設】** | **判定条件（連続量）と撤回内容（離散ジャンプ）が対応していない**（§5-0f） |

### 5-0c. 【第5次で新設】D-11: 「何が起きたら撤回するか」を決める節が、最も検証の薄い節になっていた

反証テスト群は設計条件を5つ自ら書いておきながら、そのうち3つに違反していた:

| 条件 | 違反 |
|---|---|
| (2) 閾値の作り方を先に固定する | 典拠として挙げた条項が**存在しなかった**。かつ T1・T3 の閾値はモデル出力から作られていた（M16） |
| (3) どの観測値も必ずいずれかの判定に落ちる | **T2 が値域を分割していなかった**（C6） |
| (5) 交絡を列挙する | **T1 から最有力の交絡（S_0 の反落）が欠落**、T10 の交絡が「ラグ」と誤記（C5・C7） |

> **反証テストは「自分の主張を壊す条件」を書く節である。他のどの節よりも敵対的な検査を要するのに、最後に作られたために最も検査が薄かった。**

### 5-0d. 【第6次で新設】D-12: 結合でしか制約されない量を、周辺に分解して比較した

> **D-12: あるデータが制約するのが2つのパラメータの結合（例: S\* = I/(1−ρ)）であるとき、各パラメータの周辺レンジ（＝結合許容集合の射影）を独立の「許容域」と呼んで一次元感度に使ってはならない。射影の端点は「相手を最適に選べば到達できる」点であって、相手を採用値に固定したまま到達できる点ではない。**

第5次 C1 の対処として作った群A/群B の分割が、まさにこれを踏んだ（R6-1）。端点9点すべてが結合制約の外にあり、「I が最大の分散源（27.7pt）」という順位づけは**許容されない反実仮想どうしの差**だった。

**D-8（識別できない量にも当てはまり制約がかかる）の裏面である。** D-8 は「識別できないからといって幅をそのまま感度にするな」と言い、D-12 は「その制約は結合にしかかからないので、周辺に分解して比べるな」と言う。

**検出法**: 一次元感度の幅（27.7pt / 18.3pt）が、同じ制約下の同時スキャンの幅（14.0pt）を**超えていたら**、較正が壊れている。制約が本物なら、一度に1つ動かした幅が同時に動かした幅を超えることはありえない。**この不等式は機械的にチェックできる。**

### 5-0e. 【第6次で新設】D-13: 検証手続き自身のメタパラメータが、宣言も感度分析もされていなかった

> **D-13: 検証手続きにも自由度がある（格子の刻み、許容率、除外する観測点の選び方、丸め区間の扱い）。結論を支える検証のメタパラメータは、モデルのパラメータと同じく宣言と感度の対象である。**

第4次 F2 が導入した S\* 許容域は、**格子の刻み**（Δρ=0.02 / ΔI=15,000）と**許容率**（MAE 最小の1.5倍）という2つのメタパラメータに依存していた。どちらも根拠が書かれておらず、感度も取られていなかった。細格子にすると「採用値は域外」という**本レポート最大の留保が反転した**（R6-2）。

同型の未検査が足切り丸めにもあった（R6-3）: **4成分のうち total だけを振る**という選択がメタパラメータであり、宣言されていなかった。振る対象を変えると幅は 7.3pt → 8.3pt になる。

**第5次 C2 は「結論側の格子が粗い」を直したが、制約側の格子は無検査のまま『最も重要な留保』を支えていた。**

### 5-0f. 【第6次で新設】D-14: 判定条件が連続量なのに、撤回内容が離散ジャンプだった

> **D-14: 反証テストの「判定条件」と「撤回内容」は同じ尺度で対応していなければならない。連続量の閾値に対して離散的な撤回（パラメータAをBに差し替える）を規定すると、閾値近傍の観測が、正しい更新とかけ離れた撤回を要求する。**

T2 は「新規＋復帰が 168,634 を下回る」（連続量）に対して「I_base を 152,442 へ寄せる」（離散ジャンプ）を規定していた。閾値ちょうどで発火しても、正しい更新（新観測を含めた5点平均の再計算）は 162,672 にしかならず、152,442 まで下がらない（R6-9）。

**正しい設計**: 撤回内容も推定手続きの更新として書く（「I_base を新しい観測を含めた直近5点平均で再計算する」）。離散的な差し替えは「その観測点が外れ値と確認された場合」のような別の条件に紐づける。

### 5-0g. 【第7次で新設】D-15: 制約を「宣言した」ことと「課した」ことを取り違える

> **D-15: 制約条件を文章で宣言しても、計算がそれを満たしているとは限らない。制約は宣言ではなく、計算後の充足チェックで担保する。**

第6次 R6-3 は「真値は加法制約 `new+ret+cont = total` を満たす」と明記したうえで、**制約を破った隅で 15.3pt を計算していた**（F1）。同じ構造が別の箇所にもあった: 群A の連続スキャンは「バックキャストが許す組だけを採る」と称しながら S\* 制約しか課しておらず、その (ρ,I) 自身の当てはまりを要求していなかった（41% が MAE 条件を満たさない、F11）。

**検出法**: 制約を書いたら、**その制約を満たすかどうかを計算の出口で assert する**。本プロジェクトでは `params.py` の `compute_i_base()` に凍結値との一致 assert を入れ（第6次 R6-4）、`phase8_consistency.py` に検査K（一次元幅 ≤ 結合許容域の幅）を入れた（第7次 F4）。

### 5-0h. 【第7次で新設】D-16: 検査器そのものが検査されていなかった

> **D-16: 「機械的に検査したから安全」と言うには、検査器が既知の誤りを検出できることを示さなければならない。検査器の緑は、検査器が機能している証拠がない限り、何の証拠でもない。**

第6次で新設した `phase8_consistency.py` は「致命 0」を出し、それが打ち切り判断の材料の1つになった。**変異テストでは検出 0 件だった**（F4）。免除条件が広すぎ、全非空行の 61% を無条件免除していた。

**対処**: 検査J（自己テスト）を組み込み、既知の誤り5件を毎回注入して検出できることを確認する。**検査器が自己テストに落ちたら「致命」として報告する。**

**この類型は D-7（検証を名乗る手続きが検証になっていない）の、検査ツール版である。** D-7 は6ラウンド前に新設されており、**その教訓を新しい道具に適用し損ねた。**

### 5-1. D-7 への対処 — 「検証」を名乗る条件

> **同じデータから同じモデルの2通りの表現を出して一致を確認することは、検証ではなく内部整合チェックである。**
> **検証を名乗るには、次のいずれかが要る: (a) 別のデータ、(b) 別の標本、(c) 別の識別戦略、(d) モデルが使っていない情報との突合。**

本プロジェクトで **(d) に該当する数少ない例**が、第3次で新設した「窓長 64±15日 のペアの生値」である。回帰係数を一切使わないため、モデルの外側から水準を制約する。**それでも 7.x の生値は 0.69〜0.83 と広く、②と誤仕様の両方を含んでしまう。**

### 5-2. D-8 への対処 — 識別できないことを結論として書く

Phase 7 v0.5 §0-3 は、**シナリオ（Bear/Base/Bull）の幅と、パラメータ識別問題の幅を並べて提示する**形に変えた。前者は「将来がどうなるか分からない」、後者は「過去がどうだったか分からない」であり、**性質が違うものを1つの確率加重値に潰してはならない。**

## 10. 本 Phase 自身の限界

1. **【第14次で更新】致命的誤りは 3 → 4 → 6 → 2 → 7 → 7 → 4 → 1 → 1 → 3 → 4 → 2 → 3 → 6 → 5 と推移した。収束していない。** 第4次で減ったのは一時的で、第5次で新しい成果物を作った途端に7件出た。**同じことが第10次（新規作成物2本）でも起きている。第14次の3件は逆で、「新しく作っていない期間」にこそ古い数値が下流に滞留し続けていた —— 作らなければ誤りは増えないが、**すでに入っている誤りは消えない**。**
   **すなわち件数の減少は「品質の向上」ではなく「新しく作っていない期間」を意味していた。** 打ち切りの根拠は依然として「見つからなくなったから」ではなく「やめたから」である。
2. **突合は Markdown 成果物とスクリプトの間で行った。** 生データ（CSV）の取得・変換の正しさは Phase 2/6 の三者突合に依存しており、本 Phase では再検査していない。
3. **§6 の表の「✓」の多くは網羅的な検査ではなく目視確認である。** 監査の記録であって証明ではない。
4. **本 Phase 自身が Fable レビューを受けていない。** 監査者の監査がない。
5. **最も大きな誤り（第2次の定式化欠落）が見つかったのは、D-1 への対処としてスクリプトを書いたからである。** すなわちこの誤りは「探して見つけた」のではなく「別の作業の副産物として露見した」。**同種の誤りが他にどれだけ残っているかは、同じ作業を他の量にも行うまで分からない。**
6. **前ラウンドの修正・作成が次ラウンドの致命的誤りを作るというパターンが5ラウンド一貫している。** 第3次の6件中3件、第4次の要修正7件中4件、**第5次の7件中6件**がそれである。**成果物を作れば誤りが入る。修正回数を増やせば単調に良くなるという前提は成り立たない。**
7. **第4次で初めて「不確実性が過大」という向きの所見（F2）が出た。** それは**検証を1つ実行した**（バックキャスト）ことによる。**監査が幅を広げるのは『まだ検証していない量』についてであり、検証を実行すれば幅は狭まる。** §9 に残る未検証項目（特に #2 ρ の識別、#3 二重計上疑い、#8 系列相関）は、同様に実行可能な検証で狭められる可能性がある。
8. **バックキャストは真の out-of-sample ではない。** ρ・I とも 7.x のデータから推定されているため、モデルの関数形と初期条件の妥当性を測るにとどまる。**それでも ρ=0.8303 を棄却するには十分だった**（MAE 22.5% 対 6.6%）が、採用値 0.7904 の正しさを積極的に支持するわけではない。
