# 分析の整合性

## 使う場面

次が**すべて**当てはまるとき。

- 分析が複数の文書を生み、そこにスクリプトで計算した数値を載せる
- 数値は改訂され、その改訂が全文書に届かなければならない
- 主張は撤回され、その撤回が全文書に届かなければならない
- 文書が生成器から乖離しうる程度に長く続く

単発の notebook や1回きりの回答には**使わない**。

## なぜ必要か

多文書の予測分析を15ラウンド敵対的に査読したところ、**同じ根本原因が、名付けて文書化したあとも毎ラウンド再発した**。

| ID | 失敗 |
|---|---|
| D-1 | 生成器を追わなくなったベタ書き定数 |
| D-2 | 他文書へ伝播しない撤回 |
| D-4 | 基準が揃っていない比較（窓長・足切り・基準世代・名目 vs 恒常為替） |
| D-13 | 検証手続き自身の未宣言メタパラメータ（格子の刻み・許容率・**走査箱**） |
| D-16 | 検査器そのものが検査されていなかった |
| D-17 | 検査器の合格条件が「旧値が残っていない」ではなく「正しい値がどこかに存在する」だった |
| D-18 | 16文書中2文書しか見ていない検査器で「機械的に検査した」と称していた |

**根本原因を名付けても再発は止まらなかった。止まったのは構造的に不可能にしたときだけである。**

## 手順

### 1. 正典パラメータの登録簿を作る

派生値の単一の情報源をモジュール1本に置く。

```python
# params.py
RHO = compute_rho()          # 導出する。手で書かない
I_BASE = compute_i_base()    # 導出する。手で書かない
FORBIDDEN_I_MIXED = 191905   # 使用禁止: 足切り基準が混在。**理由とセットで**記録する
```

規則:

- **派生値をスクリプトにも文書にも書き込まない。** 同じ値が2箇所にあれば、いずれ片方が腐る。
- 使わないと決めた値も**なぜ禁止なのかとセットで**ここに残す。残さないと再導入される。
- **ラベルも数値である。** `f'ρ=0.7904 / I=168,634'` のような文字列は事実上のベタ書きで、実際に使う値から必ずずれる。ラベルも導出する。

### 2. 検査器を「不在検査」として書く

これが最も重要で、最も習得に時間がかかった。

```python
# 誤り — 1文書に残っていれば、他が全滅していても通る
found = any(want in open(d).read() for d in DOCS)

# 正しい — 正典値ごとに旧世代を列挙し、どこにも残っていないことを確かめる
STALE = {'171,160': ['168,634'], '835,731': ['804,552', '804,579']}
for current, olds in STALE.items():
    for old in olds:
        for d in DOCS:
            lines = open(d).read().splitlines()
            for i, line in enumerate(lines):
                if old in line and not in_correction_context(lines, i):
                    fail(f'{d}:{i+1}: 旧世代の値 {old}（現行 {current}）が残存')
```

`in_correction_context()` の免除は、**値が書かれている行を中心とする狭い窓**（その行＋前3行＋後1行）に**宣言語**（訂正・撤回・使用禁止・旧値 など）がある場合に限る。2つのノブを同時に緩めると検査器は黙って何も検出しなくなる。

- **窓を広げない。** 広げると離れた場所の無関係な語（例: 「監査」）が免除に働き、検出 0 件になる。
- **マーカーは宣言語だけ。** 値の名前そのもの（例: `I_MIXED`）をマーカーに入れると、使用禁止値が自分自身を免除して通り抜ける（変異テストで実証）。

誤検出が増えても見逃しよりはるかにましである。

### 3. 検査の網を、結論が実際に書かれている表記に合わせる

検査器はカンマ区切り6桁以上の数値しか見ていなかった。結論はすべて `87.5万` `384億` `−13.2%` `14.7pt` と書かれており、**7ラウンドにわたって完全に網の外**にあった。

結論に使う表記を列挙し、それぞれを覆う。許容集合は**生成器の出力から作る**。手で書くと検査器のほうが腐る。

### 4. 表はセル単位で照合する

「その値が文書のどこかにある」は、要約表が旧世代のままでも正しい値が別の場所にあれば通る。行ラベルで引き当て、全セルを比べる。

```python
for line in doc.splitlines():
    cells = [c.strip().replace('*','') for c in line.split('|')[1:-1]]
    if label not in cells[0]: continue
    for got in cells[1:]:
        if is_numeric(got) and got not in expected:
            fail(f'行「{cells[0]}」のセル {got} が現行値と不一致')
```

**列数で行をスキップしてはならない。** `len(cells) < 5: continue` という一行が、まさに旧値の住んでいた4列表を丸ごと免除していた。

### 5. 撤回した「文章」の登録簿を別に持つ

数値の滞留検出では撤回された文は見えない。語句で登録する。

```python
RETRACTED = [
    ('2017年以降4つのまま', '日本の DC 数（第11次で撤回）'),
    ('値上げは予兆が見えない', '値上げの予兆観測（第12次で撤回）'),
    ('定義上打ち消される', 'ρ・I が補正で打ち消される（第14次で撤回）'),
]
```

撤回は**言い換えごとに別エントリ**で登録する。同じ主張が別の表層形（「予兆は見えない」/「予兆が見えないが」等）で残っていれば、1語句だけでは検出できない。生成器が実際に使いうる全表層形を列挙する。誤検出より見逃しを優先する。

これが無かったため、撤回済みの主張が3ラウンド分、公開用レポートに残ったまま検査器は「異常なし」を出し続けた。

撤回の理由・回次はこの登録簿を単一情報源とし、文書へは再掲しない（再掲するとまた腐る）。文書に訂正履歴を残す場合は、**撤回語句と同じ行**に宣言語（撤回・訂正）を付して手順2の免除に乗せる。文の撤回検査の免除は数値の不在検査より狭い（同じ行の宣言語のみ。マーカーは撤回・訂正に限り、「使用禁止・旧値」は使わない）。撤回済みの文を同じ行で訂正なしに書くことは、実際上ほぼ起こらない。

### 6. 検査器を変異テストする

**緑の検査器は、既知の誤りを捕まえられると示すまで何の証拠でもない。**

```bash
cp report.md /tmp/bak
sed -i 's/−13.2%/−11.9%/g' report.md    # 旧世代の値を再注入
./verify.sh | grep 要修正                # 必ず発火すること
cp /tmp/bak report.md
```

注入は**結論が実際に使う表記**で、かつ**全出現箇所**に対して行う。1箇所だけの注入は、別の場所に残った正しい値のせいで誤って通る。最初に作った検査器は、注入した5件を**0件**検出した。

### 7. 再発する誤りは、検出をやめて構造的に不可能にする

同じ誤りが3ラウンド以上戻ってきたら、検出を強化するのではなく、書けなくする。

```python
class ScaleMismatch(AssertionError): pass

def compare(d1, d2, field='normalized', unify_regime=True):
    """2点を比較する唯一の正規手続き"""
    if field == 'raw' and not unify_regime:
        raise ScaleMismatch('raw どうしの比較は窓長も基準も揃っていない')
    if not unify_regime and r1['regime'] != r2['regime']:
        raise ScaleMismatch(f"基準が違う（{r1['regime']} / {r2['regime']}）")
    ...
```

探索範囲を持つ手続きは、**範囲を必須引数にし、結果に同梱して返す**。範囲を書かずに答えを引用できなくなる。

```python
def scan(tol, box):                # box は必須引数（デフォルトなし）。書かずに引用できない
    ...
    return lo, hi, n, box          # 箱が答えと一緒に動く
```

**そのうえでガードが実際に発火することを検査する。** 発火しないガードは飾りである。

### 8. 検査圧の分布を宣言する

どの検査がどの文書を覆っているかを書く。16文書中2文書しか見ずに「機械的に検査済み」と言うのは範囲不明の主張である。覆っていなかった14文書から出た致命的5件は、**すべて検査器が既に検出できる型**だった。

## 検証

整合していると主張する前に:

- [ ] `./verify.sh` が 致命0 / 要修正0
- [ ] 全文書の派生値が登録簿に辿れる。手で書かれた値がない
- [ ] 変異テスト: 旧世代の値を**結論の表記で・全出現箇所**に再注入 → 検出される
- [ ] 変異テスト: 要約表のセルを旧値にする → 検出される
- [ ] 変異テスト: 撤回済みの文を再注入 → 検出される
- [ ] ガード自身のテストが発火する（基準不一致の比較が例外になる）
- [ ] 各検査の対象文書が明記され、それが全文書である

## 落とし穴

**件数や内訳を、分類し直さずに足して更新してはならない。** 4分類の内訳を2ラウンドかけて 45 → 60 に増やしたが、総数は 58 で合わなくなっていた。分類をやり直していなかったからである。やり直せないなら、元の内訳を「45件時点の分類」と明記して凍結し、以降の追加は別建てで数える。

## 同梱スクリプト

検証ツールチェーン一式を同梱している。`20260830_1/` はアーカイブで、**ここが正典**。

| パス | 役割 |
|---|---|
| `verify.sh` | エントリポイント。全成果物の横断チェックを起動 |
| `scripts/` | 全27スクリプト（`phase8_consistency.py` が全て実行する） |
| `data/` | 計算・検証が読む CSV |
| `docs/` | 照合対象の文書 |

実行はスキルのルートで `./verify.sh`（期待出力は 致命 0 / 要修正 0）。`verify.sh` は UTF-8 モードで起動するため Windows でもそのまま動く。

> **`data/census_world/` の第三者データは同梱していない。** 取得手順は `data/census_world/SOURCE.txt` にのみ記載。このため `phase6_model.py` と `phase9_japan.py` が実行できず、`./verify.sh` は **致命 3** を報告する（データ取得後は 致命 0）。
