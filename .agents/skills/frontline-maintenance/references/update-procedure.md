# パッチ後の更新手順

新しいパッチや HotFix が出たときに、値台帳とページを現行に合わせる手順。調査のしかたは [research-method.md](research-method.md) に従う。

## 0. きっかけ

- パッチノート一覧（https://jp.finalfantasyxiv.com/lodestone/special/patchnote_log/ ）に新しい版が出た
- Lodestone の「更新のお知らせ」に HotFix が出た
- ファンフェス・プロデューサーレターLIVE で PvP の変更が告知された（実装前なので、台帳は変えずにメモだけ残す）

## 1. 変更点を集める

0. まず `python -I frontline/tools/check_official.py` を回す。「不一致」が出た行は、公式ページの記述が変わった候補として変更メモに入れる（一致していても、新しいパッチノートに変更が書かれている場合があるので、下の手順は省略しない）。
1. 新しいパッチノートの生の HTML を取得し、PvP の節とフロントラインに関係する記述を抜き出す（ルール名、オブジェクト名、「勝利に必要な」「ノックアウト」「戦意」「リミットゲージ」「ジョブ補正」「日替わり」などで検索）。
2. HotFix と不具合告知も同じように確かめる。
3. 公式フロントラインガイド6ページを取得し直し、共通の3表（順位別LB補正・戦意高揚・ジョブ補正）を機械的に読み、前回の台帳と比べる。5ページで表が同一かも確かめる。
4. 公式ジョブガイドの PvP タブから、各ジョブの LB 基準蓄積時間を読み直す。
5. 見つけた変更を「変更メモ」として一覧にする（パッチ、該当する原文の抜粋、影響する台帳の行 ID）。

## 2. 台帳を直す

変更があった行ごとに:

1. 「値」を新しい値にする。
2. 「最終変更」を新しいパッチにする。
3. 「現行確認」を「<新パッチ> ✔公式」にする。
4. 「出典」に新しいパッチノートの出典 ID を足す（出典台帳にも行を足す）。
5. 「根拠」の表の原文抜粋を差し替え、`frontline/data/official/<出典ID>.md` に抜粋を保存する。
6. 「採否」は、公式で原文照合済みなら ○ にしてよい。それ以外は空欄にしてユーザーに判断を頼む。 公式でない行は、値を直すと判定の記録（`frontline/data/judgments.md`）と合わなくなり、validate が止まる。値を直したら必ず採否を空欄に戻す。
7. 旧値を、旧値の登録簿 `frontline/data/retired.md` へ入れる（行ID・旧値・範囲・使わない理由・時期）。
8. その行に表示文（「## 表示文」の表）があれば、検査で止まる。表示文を見直して `python frontline/tools/ledger.py set-display <ID> <表示文>` で書き直す。値にない数は書けない。

変更がなかった行は:

- 公式の行: 新パッチのノートで変更がないことを確かめたら、「現行確認」だけを「<新パッチ> ✔公式」に上げる。
- 外部・実測・未確認の行: 「現行確認」の番号は上げない。仕様の変更で効きそうなもの（同じルールの別の値が変わった場合など）は、ゲーム内確認リストに再確認を足す。

仕組みごとなくなった値（ルールの廃止・改修）は行を消さず、採否を × にしてコメントに理由とパッチを書く。

## 3. 日替わりのローテーション

- パッチノートに「日替わり」「開催ルール」の変更があれば、周期の順序を直す。
- 周期の起点（どの日がどのルールか）は、ユーザーにゲーム内で1日確認してもらって確定する。確定するまでは、トップページの「今日のルール」を誤って案内しないよう、起点の行を未確認のままにする。

## 4. ユーザーに確認を頼む

- 変えた行の一覧（行 ID、旧値 → 新値、根拠）と、ゲーム内確認の依頼をまとめて渡す。
- 変えた行の「採否」は空欄にしておき、`python frontline/tools/review_page.py` で確認用ページを作って渡す（「未判定だけ」で変えた行だけが出る）。
- 書き出された判定の JSON を `python frontline/tools/apply_review.py <ファイル>` で取り込む。コメントの訂正は、出典を確かめてから値に入れる。 取り込みのツールが判定の記録（judgments.md）も書く。

## 5. 検査して生成する

1. `python frontline/tools/ledger.py validate` がエラー 0 になるまで直す。
2. `python -I frontline/tools/check_official.py` が不一致 0 になることを確かめる。
3. `python frontline/tools/build.py` でページを作り直す。「生成できない」と出たら、メッセージの行（× や空欄の行を参照している、単位が変わった、時間帯の条件が合わないなど）を見て、台帳か `frontline/tools/pages.py` を直す。
4. `python -m pytest tests/frontline` を通す（数字の出どころ・× の行と旧値の不在・4つの表示領域でスクロールなしと文字24px以上・今日のルール・検査器の変異テスト）。新しい行を出してはみ出したら、何かを短くするか削る。
5. ヘッダの「データ <パッチ> 時点」が新しいパッチ番号になっていることを確かめる（COM-META-PATCH）。

## 6. 報告する

- 変えた行、確かめたこと、確かめていないこと（未確認のまま残した行と理由）を書く。
- 「すべて検証した」とは書かない。何を見て何を見ていないかを書く。
- コミットとプッシュはユーザーの指示に従う。
