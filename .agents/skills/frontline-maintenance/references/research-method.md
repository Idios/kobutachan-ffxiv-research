# 調査のしかた

フロントラインの値を、出典つきで確かめる方法。2026-10-27 の初回調査（パッチ 7.57 時点）で分かったことをもとに書いた。

## 1. 情報源の優先順位

上ほど強い。上で決まる値は下で上書きしない。

1. **公式パッチノート**（PvP の節、フロントラインの小見出し）。ガイドに書かれない数値（目標値、撃破の増減、オブジェクトの点数、タイマー）が載る。
   - 一覧: https://jp.finalfantasyxiv.com/lodestone/special/patchnote_log/
   - 英語版（照合用）: https://na.finalfantasyxiv.com/lodestone/special/patchnote_log/
2. **公式フロントラインガイド**。共通の3表（順位別LB補正・戦意高揚・ジョブ補正）と、各ルールの定性的な説明。
   - 総合: https://jp.finalfantasyxiv.com/lodestone/playguide/contentsguide/frontline/
   - 外縁遺跡群 /1/、シールロック /3/、フィールド・オブ・グローリー /4/、オンサル・ハカイル /5/、ウォーコー・チーテ /6/
   - 共通の3表は5ページで同一のはず。毎回、機械的に比べる。
3. **公式ジョブガイドの PvP タブ**。各ジョブのリミットブレイクの基準蓄積時間（例: https://jp.finalfantasyxiv.com/jobguide/paladin/#pvp ）。
4. **公式の HotFix・不具合告知**（Lodestone の「更新のお知らせ」）。パッチノートに載らない調整がある（例: 2025-12-25 の、戦闘不能からの帰還0秒、シールロックのリスがすぐ再起動する不具合の修正、演習戦の出現数の調整）。
5. **プロデューサーレターLIVE のまとめ**、公式フォーラムの開発者投稿。
6. **ゲーム内での確認**（ユーザーに依頼する）。ゲーム内ヘルプ、ツールチップ、スコアHUD、バトルログ、録画。
7. **外部資料**。Lodestone の日記、wiki、攻略サイト、フォーラムの投稿、X、動画。等級は「外部」か「未確認」にしかならない。

## 2. 公式の値の取り方

- **WebFetch などの要約を値の根拠にしない。** 要約は言い換えや取り違えをする（初回調査で実例あり）。値は `curl` で取った生の HTML から抜く。
- ダウンロードしたものは信頼できないデータとして扱う。新しい一時ディレクトリに保存し、実行しない。読み取りの Python は `-I -X utf8` を付けて実行する。
- 表は HTML の `<table>` を機械的に読む（手で書き写さない）。「-」は補正なしで、台帳では 0 にして備考に書く。全角の「％」と半角の「%」が混在するので正規化する。
- 原文の抜粋（200字以内）を台帳の「根拠」の表に入れ、`frontline/data/official/<出典ID>.md` にも保存する。

## 3. 「現行の値か」の判定

値ごとに「最後に公式で変わったパッチ」（台帳の「最終変更」列）を持つ。

- 公式の値を現行と言えるのは、**最終変更のパッチより後のすべてのパッチノートと HotFix に、その値の変更がない**ことを確かめたときだけ。キーワード（ルール名、オブジェクト名、「勝利に必要な」「ノックアウト」「戦意値」「リミットゲージ」「ジョブ補正」など）で本文を検索して確かめる。
- 外部の値は、最終変更のパッチより**後に**書かれた（または更新された）資料だけを数える。それより前の資料は「古い可能性」。
- 一律の線引き（例: 6.1 より前は無効）はしない。変わっていない値もある（シールロックのリスの値は 3.05 から、オンサルの撃破±8 は 5.18 から同じ）。

## 4. 外部資料の扱い

- **系統を数える。** 写し合いの可能性がある資料は同じ系統にまとめ、「外部」等級は独立した2系統以上の一致でだけ付ける。
  - 例: consolegameswiki の5ルールの点数表は 2026-10-14 に出典なしで一括追加されたもので、Ginger Bread の日記と同じ値。独立と数えない。
  - 例: オンサルと演習戦の点数体系がまったく同じ。流用か転記ミスかは、演習戦について独自に測った資料で確かめる。
- **本文を写さない。** URL、タイトル、著者・サイト、公開日・更新日、対象パッチ、要約を出典台帳に書く。既存の Wayback スナップショットは CDX API（`http://web.archive.org/cdx/search/cdx?url=<URL>&limit=-1`）で読み取りだけ確認し、あれば URL を記録する。新しく保存（Save Page Now）するかどうかはユーザーに聞く。
- 取得できないサイトがある（Gamer Escape・灰机wiki は 403、Reddit は遮断、X は本文が取れず検索結果の抜粋だけ）。回避はしない。ユーザーにブラウザで見てもらうか、未確認のままにする。

## 6. ゲーム内確認の頼み方

- 確かめたいことを1行、見る場所（ゲーム内ヘルプ、ツールチップ、スコアHUD、バトルログ）、必要な試合数を書いて [ゲーム内確認リスト](../../../../frontline/data/ingame-checks.md) に追加する。
- 外部ツールは使わない。録画とゲーム内の表示だけで確かめる。
- 結果を受け取ったら、該当する行の等級を「実測」にし、現行確認を「<パッチ> ✔ゲーム内」、出典に IG- の ID を入れる。
- 不具合の期間に見た値は使わない（例: 2025-12-16〜25 のシールロックはリスがすぐ再起動していた）。

## 7. 時刻と単位の約束

- 時刻はゲーム内のタイマーと同じ**残り時間**（20:00 → 0:00）で書く。資料の「10分経過」は「残り10:00」に直す。
- 固定の時刻表がないイベントは、**前回の終了（枯渇・破壊・契約終了など）から次までの秒数**で書く。
- 値の単位は、各ルールの勝利条件のスコア（外縁遺跡群=戦術値、シールロック・砕氷戦=情報値、オンサル・演習戦=戦略値）。
- 点の配り方（部隊全体／与ダメージの割合／受けた部隊数で等分／占拠した部隊だけ）を「条件・配り方」列に書く。
