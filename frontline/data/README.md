## 確認のしかた（○×とコメント）

### おすすめ: 確認用ページで付ける

表が大きくてエディタでは付けにくいので、ブラウザで1行ずつ付けられるページを用意した。

1. `python frontline/tools/review_page.py` を実行する（台帳から `reports/20261027_1/review/index.html` を作る）。
2. そのファイルをブラウザで開く。ルールで絞り込み、「未判定だけ」を表示し、行ごとに **○ / ×** を押す。値を直したいときはコメント欄に書く。根拠と出典は各行の「根拠と出典」を開くと見られる。判定はブラウザに自動で保存される（途中でやめてよい）。
3. 終わったら「判定を書き出す」を押す。`frontline-review-日付.json` がダウンロードされる。
4. `python frontline/tools/apply_review.py <そのファイル>` で台帳に取り込む（Claude にファイルを渡してもよい）。判定したあとで値が変わった行は取り込まず、警告を出す。

### 表を直接書き換える場合

各台帳の「## 値」の表で、**採否**列と**コメント**列だけを書き換える。

- 採用するなら `○`、採用しないなら `×` を書く。
- 値を直したいときは、コメント列に書く（例: `× 正しくは -8`、`○ ただし表示は「約5秒」に`）。値の列は直接書き換えなくてよい（出典を確かめてから反映する）。
- 公式の行は、原文との照合が済んだものを既定で `○` にしてある。違和感があれば `×` に変えてコメントを書く。
- 判断がつかない行は空欄のままでよい。空欄と × の行はページに出さない（生成器が止まるので、出しようがない）。
- 公式でない行（外部・実測・未確認）は、○ を付けたときの値を判定の記録（judgments.md）に残す。あとで値だけが書き換わると、記録と合わなくなって検査で止まる（あなたが見ていない値は公開されない）。値を直したら採否を空欄に戻し、確認用ページで判定し直す。

## 表の列の意味

| 列 | 意味 |
|---|---|
| 等級 | **公式**（公式ガイド・パッチノート・ジョブガイド・HotFix 告知の値）／**外部**（公式ではないが、現行期の独立した2系統以上の資料が一致）／**実測**（あなたがゲーム内で確認した値）／**未確認**（1系統だけ・食い違い・古い資料のみ・見つからない） |
| 最終変更 | その値が最後に公式で変わったパッチ（記録がなければ「記録なし」） |
| 現行確認 | 現在のパッチ（7.57）で有効かどうかの確認状況。✔＝確認済み、△＝外部の現行期の資料だけ、？＝未確認 |
| 出典 | 出典台帳の ID。OF- は公式、EX- は外部、IG- はゲーム内確認 |

「## 根拠」の表に、公式の原文抜粋と備考（検証役の訂正・食い違いの説明・ゲーム内確認の手順）がある。

## 表示文（ページでの短い言い方）

文字を大きくしたページに長い文は入らないので、一部の行には「## 表示文」の表で短い言い方を決めてある（確認用ページでは「ページでの表示」として出る）。

- 表示文は値を言い換えただけで、事実を足さない。値にない数は書けない（検査で止まる）。
- 値を書き換えると、表示文の「元の値」と合わなくなり、検査で止まる。表示文を見直してから `python frontline/tools/ledger.py set-display <ID> <表示文>` で書き直す（元の値は今の値になる）。

## ゲーム内確認

[ingame-checks.md](ingame-checks.md) の「結果」「確認日」「パッチ」の列に書き込むと、該当する行を「実測」に格上げする。外部ツール（ACT・Dalamud など）は使わず、録画とゲーム内の表示（スコアHUD・バトルログ・チャットのタイムスタンプ）で確かめる。

## ページの作り方

- `python frontline/tools/build.py` … 台帳から公開ページ（`frontline/index.html`・`frontline/<ルール>/`・`frontline/jobs/`・`frontline/sources/`）を作る。採否が ○ の行しか使わない。
- `python frontline/tools/build.py --check` … 生成物が台帳と合っているかだけを確かめる。
- ページの中身（どの行をどこに出すか）は `frontline/tools/pages.py`、見た目は `frontline/assets/site.css`。
- 等級（公式・外部・実測・計算・未確認）は台帳にだけ残し、ページには印も凡例も出さない（2026-10-29 の指示。情報のノイズになるため。間違いは指摘を受けたら直す）。出すときは `build.py` の `SHOW_GRADES` を True にする。
- ページの下の「このサイトについて」は [../README.md](../README.md)（公開向けの説明・権利・出典・間違いの知らせ方）にリンクする。「© SQUARE ENIX」はスクウェア・エニックスの著作物利用条件 3-1 で各ページに1か所必要なので、ページの下に残す。

## 機械検査

- `python frontline/tools/ledger.py validate` … 列・ID・等級・出典の参照・原文抜粋の有無・表示文の古さ・判定の記録との一致（公式でない ○ の行）・値に使えない文字（改行・波括弧）を検査する。
- `python -I frontline/tools/check_official.py` … 公式の行の原文抜粋が、公式ページに今も載っているかを照合する。
- `python -m pytest tests/frontline` … ページの数字がすべて ○ の行に辿れるか、× の行と旧値がページにないか、4つの表示領域でスクロールなし・文字24px以上か、今日のルールが合っているかなど（ブラウザを使う検査は Chrome か Edge が要る）。

保守の手順（パッチ後の更新）は `.agents/skills/frontline-maintenance/` にある。
